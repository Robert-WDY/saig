# 武汉接线台 · 冲击入选的开发规划

> 写于 2026-11-20。目标：进入 SAIG 线下赛 108 席。
> 依据：官方《SAIG 数命SPU国际AI大赛说明》、官网赛规、本仓库实测。

## 1. 先看清「入选」怎么算

| 通道 | 名额 | 决定因素 | 我们能做的 |
|---|---|---|---|
| 人气直邀 | 18 | 报名表里那**一条**视频链接的点赞数，11-20 23:59 截止 | 今天发布并集中拉赞，详见第 6 节 |
| 赛区选拔 | 3 赛区 × 30（AI 从业者 / 非从业者各 15） | 导师审核，四项功能各 25 分 | 本文主体 |

时间线：官方说明写报名 **11-20 截止**、**11-23 公布入围**。官网目前写的是「截止时间待公告」。保险起见，按今天截止来办，今晚之前必须完成报名。评委评审大概率集中在 11-20 至 11-23 这几天，所以**评委能用到的版本，必须在 48 小时内上线并保持稳定**。

## 2. 主办方真正想要什么

官方说明的最后一段才是这道题的出题意图：

> 「打造面向武汉来宾服务的城市 AI 接待员，提供**信息咨询、导览和多语言接待**等服务。……由 AI 承担具体服务，由**真人运营者或团队负责维护、交付并承担结果责任**。」（配套月薪 1 万美元的岗位设想）

所以评委心里的标准，不是「做了个能聊武汉的机器人」，而是：

**「这个东西明天能不能放到武汉的来宾面前上岗，出了问题有没有人能运营它。」**

大多数参赛作品会停在「套一个大模型 + 一份资料 + 一个聊天框」。我们的差异化，应该全部朝「可上岗」这个方向长。

## 3. 我们已有的、别人很难有的

1. **句句有出处**：回答绑定官方手册的页码原文，可以点开核对。接待员不能乱说话，这一点正中要害。
2. **真能把行程排出来，改口也接得住**：排程器是确定性的，给出真实路网和地铁转场，校验约束，改动有差异高亮。别人多半只会让大模型写一段「第一天上午去黄鹤楼」。
3. **官方形象**：江豚是赛事官方的虚拟形象，有动画和语音。
4. **一镜到底的演示片**：已经发布。

**当前的短板（实测）**：开放式对话很脆。例如：

- 「太累了，少两个点」被答成「沿用当前行程」；
- 「晚上呢」把内部检索语句漏给了游客；
- 「我住光谷」直接报「未收录」；
- 「下午半天」仍从 09:00 排起；
- 「老人走不了远」这个约束被丢掉了。

根因是现在的内核：约 40 个串联的意图分类提示，由程序决定路线，只认预先设计过的说法。**评委一定会随口问，所以这是第一优先级。**

## 4. 决策：先把已有功能做深做稳，只加三个和出题意图强相关的新能力

| 优先级 | 做什么 | 为什么 |
|---|---|---|
| **P0** | **内核换成工具调用式智能体**（参照 ChorifyCore），保证评委怎么问都接得住 | 不修这个，其他都白做 |
| **P0** | **评委零门槛试用**：公网地址，免邀请码，限流，手机扫码即用，流式输出 | 评委打不开、等太久，就直接零分 |
| **P1** | **多语言接待**（中 / 英 / 日 / 韩） | 出题意图原文点名；官方素材本身就是四语 |
| **P1** | **来宾模式：为 12 月线下赛的选手和评委当接待员** | 「评委自己就是游客」：天河机场 / 汉口站到智民里、12-17 签到、比赛期间的半日游 |
| **P2** | **运营台**：未答问题清单、资料一键更新、对话质量抽检、访问统计 | 对应「真人运营者维护」，也为赛后 3 个月市场验证打底 |
| **P2** | **前台大屏 / 语音模式**：对着江豚说话，它开口回答 | 「接待员」的实体形态，路演效果强 |
| 不做 | 与接待无关的炫技功能（图像生成、小游戏等） | 分散精力，评委不加分 |

### 4.1 P0 新内核（参照 ChorifyCore）

**一个决策循环**：模型看到工具清单和 Skill 索引，自己决定下一步调用哪个工具；程序只负责执行，并把真实结果原样回给模型，直到模型给出最终回答。没有关键词路由，也没有程序预设的阶段。

| 工具 | 实现 | 性质 |
|---|---|---|
| `search_knowledge(query, topics)` | 现有 BM25 + LSA 检索 | 只读，可并行 |
| `read_source(id)` | 读取出处全文 | 只读 |
| `find_place(name)` | 地点、片区、就近地铁和导航；未收录时给出最接近的候选 | 只读 |
| `get_trip()` | 读取当前行程卡 | 只读 |
| `plan_trip(days, start, end, origin, must, avoid, pace, …)` | 现有确定性排程器 | 写，一步一个 |
| `edit_trip(day, ops[])` | 平移时间、删站、加站、换站、设起止；保留原站，排不下时如实报冲突 | 写，一步一个 |
| `read_skill(id)` | 方法说明：初访讲解、行程规划、社区参访、SAIG 指南、来宾接站 | 只读 |
| `remember(fact)` | 本会话记忆：称呼、住处、同行人、偏好 | 写 |

从 ChorifyCore 借来的规则：

- 工具参数先过 JSON Schema 校验，出错时把真实错误回给模型；
- 每轮有步数预算（≤6）和超时（≤45 秒），到点就如实说明，不编造结果；
- 原始消息只追加、不改写；
- 较早的对话压缩成摘要，原文仍可按 ID 读取，这就是基础记忆；
- 写操作一步只做一个，只读工具可以并行，以保证速度。

**出处校验从「每句一次大模型复核」改为程序核对**：最终回答引用的 `[n]` 必须来自本轮真实检索到的原文，否则删掉引用并降级措辞。行程卡里的时间全部来自排程器，模型无权编造。

**流式输出**：通过 SSE 推送「正在查资料 / 正在排路线」等真实步骤，再逐字输出回答。

**旧内核保留为回退**，用开关切换；两套内核跑同一份对话题库对比，新内核全面不差才切换。

**验收标准**（新增对话题库，覆盖上面实测失败的说法，至少 40 轮多轮对话）：

| 指标 | 目标 |
|---|---|
| 意图正确率 | ≥ 95% |
| 内部信息泄漏 | 0 |
| P95 首字时间 | ≤ 3 秒 |
| P95 完整回复（不含排程） | ≤ 8 秒 |
| P95 完整回复（排程） | ≤ 15 秒 |
| 回合级报错 | 0 |

### 4.2 P0 评委体验

- 公网 HTTPS 地址加二维码，写进报名简介和视频简介；
- 去掉邀请码门槛，改为按 IP / 会话限流加全站日额度；
- 首屏 10 秒看懂：四张卡片、「评委快速体验」一键引导四项功能、示例问题；
- 任何错误都有人话兜底，并给出「换个问法 / 重试」按钮，绝不出现技术报错；
- 上线前跑一遍全量对话题库，部署后每小时做一次健康探测。

### 4.3 P1 多语言

- 界面文案四语切换；回答语言跟随提问语言（英文已验证可行）；
- 检索同时用中文原文和官方英 / 日 / 韩版素材；专有名词用固定译名表；
- 语音播报跟随回答语言。

### 4.4 P1 来宾模式（12 月线下赛）

- 资料：签到时间地点、智民里会场、天河机场 / 汉口站 / 武汉站到江岸的地铁、比赛期间作息；
- 一句话安排：例如「我 12-17 下午到汉口站，签到后想逛两小时」；
- 首页入口「来参加 SAIG 线下赛？」。

## 7. 风险

| 风险 | 对策 |
|---|---|
| 新内核在 48 小时内不稳 | 旧内核开关回退；题库不过就不切换 |
| 模型服务限流或故障 | 健康探测；降级为检索 + 模板回答；页面提示 |
| 评委流量突增，额度耗尽 | 全站日额度调高；按会话限流；监控告警 |
| 资料过期（赛程变动） | `official.json` 带核对日期；运营台一键更新 |
